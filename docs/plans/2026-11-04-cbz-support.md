# CBZ 扫描与阅读支持方案

日期：2026-11-04（Asia/Shanghai）

状态：代码、独立审查和本地可执行验证已完成；真实 ZIP/Sharp 集成测试因本地缺依赖尚未执行，已配置 CI 强制验证。

## 目标与验收行为

用户目录示例：`图库/作者名/漫画名字/封面.jpg + 漫画.cbz`。

- `漫画名字` 为一个作品，每个 `.cbz` 为一个章节，章节名取文件名去掉扩展名；文件名及包内图片按自然顺序排列（1、2、10），扩展名大小写不敏感。
- 有有效 CBZ 时，明确命名为 `cover`、`folder`、`封面` 的同级图片用作封面；若同级只有一张图片，也视作外置封面，不再生成只有封面的 `1P` 正文章节。其余散图保留原有图片章节行为。
- 无外置封面时，以第一个有效 CBZ 章节的第一页作封面；纯 CBZ 目录也能被发现。CBZ 内嵌套目录里的图片同样纳入页索引。
- 保留现有图片章节目录的分组规则，并让其中的 CBZ 进入同一作品；不把作者目录合并成作品，也不增加自动作者推断。
- 扫描后 Web 和 Mihon 均可通过现有章节页接口阅读；封面、手动封面、原图、省流及灰度图片均贯通。
- 一个坏包不阻断其他有效包或作品的扫描，扫描问题包含文件路径和原因。

## 已核对的链路与原因

1. `server/scanner.mjs:81` 的目录事实收集只收图片；`:813` 起的 flat 候选发现也只判断图片。`:1037` 实际固定使用 `scanSeriesFlat`，CBZ 没有被处理。
2. `server/scanner.mjs:619` 将目录中的所有直接图片建立为章节，所以用户的外置封面成为唯一正文页。
3. `server/store.mjs:837` 默认将章节路径与页相对路径拼成普通文件路径；运行态清空页数组，媒体实际依赖 SQLite 查询。
4. `server/database-query-worker-thread.mjs:202` 和 `:207` 的封面、页查询只返回普通文件来源；新增来源信息必须贯穿写入、重启、异步查询及复用扫描。
5. `server/routes/media.mjs` 将来源直接传给 `serveFile` / `ThumbnailService.getVariant`。后两者依赖实体图片文件，已有 HEAD、Range、ETag 及各种图片变体。
6. Web `DetailPanel.vue` 和 Mihon `FolderLibraryApi.kt` 都只消费章节页数与 URL 模板，因此无需改变公开阅读协议。
7. `server/store-schema.mjs:248` 当前 schema 不匹配会重建全部表，包括设置、收藏、进度；本次不能只增加版本号而沿用该逻辑。
8. watcher 和 scan-coordinator 已传递所有文件类型的变更路径。扫描器对图库根下文件的 dirty-path 回退目前仅识别图片，需要补 CBZ。
9. `server/exporter.mjs` 当前没有调用方，运行链路不使用本地 Mihon 导出；本次不启用或扩展该遗留能力。

## 实现设计

### 归档与来源

- 在 `package.json` 声明成熟的 `yauzl` 依赖，使用惰性条目枚举、ZIP64 和单条目读取。避免手写完整 ZIP 解析器；实际版本及使用 API 在实现时核对。
- 新增归档模块，扫描只读取目录索引，不整包解压、不把整个包装入内存。忽略非图片、目录、`__MACOSX` 和 AppleDouble 文件。
- 使用显式来源描述：`sourcePath` 为真实图片或真实 CBZ 路径；CBZ 来源另有 `archiveEntry`，保存条目序号、原始条目名、定位所需元数据、CRC/大小及归档身份。同名条目按序号区分，排序相同时以序号确定顺序。不得产生 `漫画.cbz/001.jpg` 这样的伪物理路径。
- 支持常见 ZIP Store/Deflate、ZIP64、标准 UTF-8/Unicode/CP437 文件名。加密包、不支持的压缩方式、异常条目和损坏包给出明确错误；不承诺无标记 GBK 文件名自动纠正。
- 条目验证拒绝绝对路径、父目录跳转和链接；缓存文件名由来源摘要生成，绝不使用条目路径直接拼接磁盘目标。

### 按需单页缓存及媒体

- 新增有容量、空闲期限、任务队列、并发与单页展开大小上限的原图缓存。归档条目数量及索引总量也设上限。流式读取单页，校验实际大小与 CRC32 后原子发布临时文件；相同任务合并，失败清理临时文件并允许重试。
- 缓存键包含归档绝对路径、size/mtime/ctime 及条目身份；读取前后检查归档身份，替换中的文件不发布旧结果。数据库中的条目描述过期时返回可识别错误并提示重新扫描，不能读错页。
- 原图缓存命中时不修改文件 mtime/ctime，访问时间单独维护，防止 ETag 抖动或缩略图不断重算。请求使用期间保护缓存项，避免淘汰与发送/缩略图处理竞争。
- 统一来源解析将普通图片直接交给现有链路，将 CBZ 条目解析为缓存实体图片，再调用原有图片变体和 `serveFile`。缓存保留真实图片扩展名，确保 MIME 正确。
- 不把 ZIP 缓存目录混入现有 `.webp` 缩略图缓存；增加配置、初始化、停机清理及运行状态。并发沿用资源档位提供的上限。

### 扫描及增量更新

- 候选发现同时识别图片与 CBZ；每个 CBZ 独立建立稳定章节 ID，保留原作品 sourceKey / ID。
- 指纹增加格式版本、章节身份、归档路径和文件身份、条目身份及外部封面身份；旧的封面-only 快照重新扫描后不能被错误复用。
- 补齐新增、删除、原地替换、根目录 CBZ 和分类绑定目录的增量扫描；无关作品继续复用。
- 单包错误独立记录并继续。未变化坏包的问题不能因复用而无故消失；只有坏包及封面的目录不能被伪装成已成功读取的 CBZ 作品。

### 持久化与既有用户数据

- 对当前 v4 schema 做事务内 v4→v5 增量迁移：`pages` 添加可空 `archive_entry_json`，`series` 添加可空 `cover_archive_entry_json`。普通图片字段继续有效；不清空当前用户数据。
- 同步修改存储写入、加载和数据库 worker 的页面/封面查询；来源描述不暴露到公开列表、详情或页 URL 模板中。
- 保持运行态只持有章节摘要，`_reused` 沿用数据库页索引；验证进程重启及连续复用后依然能读取 CBZ。
- 旧“封面-only”章节可能被移除。查询手动封面和阅读进度时校验引用仍属于当前作品且页码有效；失效封面回退默认封面，失效进度不用于跳转，保留原覆盖数据而非误指向新 CBZ。

## 已知限制及风险

- 加密、多分卷、不支持的压缩方式和无编码标记的 GBK 文件名不在本次支持范围；索引异常显示扫描问题，图片数据的 CRC/展开大小在实际读取时验证。
- 首次读取一个尚未缓存的页会重新遍历中央目录至目标条目；此实现优先控制常驻内存与文件句柄，大型归档首次连续阅读存在额外索引成本。
- 归档原图和图片变体各有独立磁盘限额；缓存页都在使用或解压队列已满时返回可重试错误，源包被替换而索引尚未更新时需要重新扫描。
- 当前 v4 数据库可无损升级；更旧 schema 继续沿用项目已有的重建规则。恢复旧版服务程序不属于本次兼容范围。
